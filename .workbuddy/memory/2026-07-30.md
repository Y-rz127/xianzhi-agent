## RAG 向量库未进 PostgreSQL 的根因与修复
- 现象：CloudBase 日志显示 RAG 检索正常，但 PG 里没有 langchain_pg_collection / langchain_pg_embedding 两张向量表；VECTOR_STORE_TYPE=postgres 已配置。
- 根因：langchain_postgres.PGVector 用 SQLAlchemy `create_engine`，pg_dsn() 返回的是 `postgresql://`（无后缀）默认走 psycopg2 方言；但 requirements 只装了 psycopg[binary]（v3）、缺 psycopg2 → 报 `No module named 'psycopg2'` → 静默回退 Chroma（容器本地文件）。业务表用 psycopg_pool(v3) 直连，不受影响。
- 修复（commit a1bff22）：
  1. requirements.txt 加 `psycopg2-binary>=2.9.0`（与 psycopg v3 独立共存，PGVector 与记忆池各用各的）。
  2. vector_store.py `_build_vector_store` 加后端恢复判断：配置切回高优先级（postgres）且指纹仍是回退类型（chroma）时，忽略指纹直接按配置全量重建，避免永远卡在 chroma。
- 用户侧下一步：CloudBase 重新构建/部署一次新版本容器（容器文件系统每次部署是全新的，无旧指纹），启动后应看到 `Postgres(pgvector) 向量库重建完成` 日志，PG 里出现两张向量表，且重启不再重复烧 embedding token。
- 注：此前误判过「DashScope 欠费导致建表失败」，实际与欠费无关，是依赖缺失。

## PDF 中文乱码修复（commit c8b1df5）
- 现象：真机调试手机端下载命理报告 PDF，中文全变成黑点/黑块。
- 根因：`app/tools/pdf_report.py` 字体探测列表里 Linux 路径写成 `/usr/share/fonts/truetype/noto/...`，但 Debian 的 `fonts-noto-cjk` 实际装在 `/usr/share/fonts/opentype/noto/` 且是 .ttc/CFF 轮廓；NotoSansSC 是 PostScript 轮廓，reportlab 的 TTFont 不支持（实测报 postscript outlines not supported）→ 注册失败 → 回退 Helvetica → 中文黑块。
- 修复：把 `simhei.ttf`（TrueType，reportlab 100% 支持）内置到 `app/tools/fonts/simhei.ttf` 随仓库分发（Dockerfile `COPY . .` 会进镜像）；pdf_report 优先用项目内置字体，系统字体探测修正 Debian 实际路径 + glob 兜底；`_PROJECT_FONT_DIR` 由 `data/fonts` 改为 `app/tools/fonts`（data/ 被 .gitignore 整目录忽略，字体无法随 git 提交，已避开）。
- 验证：用项目 .venv reportlab 生成中文 PDF，内嵌字体显示 `AAAAAA+SimHei` 子集，中文正常嵌入。
- 注：simhei 为微软字体，自用/小程序自用场景可接受；若后续公开分发建议换 OFL 开源字体（Noto Sans SC 的 TTF 轮廓版或文泉驿）。
