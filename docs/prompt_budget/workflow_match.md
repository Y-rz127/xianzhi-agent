# Workflow 路径 · Worker 主回答（合婚双盘场景，调用 B-match）

- **所属路径**：Workflow（`app/agent/xianzhi_workflow.py` 的 `XianzhiWorkflow`）
- **触发条件**：用户意图 `domain == "match"`（合婚/双人关系）→ `_build_messages` 选用 `match` worker（expertise = **385 字**，全 worker 最大）
- **LLM 调用点**：`xianzhi_workflow.py:1152` → `self.chat_model.invoke(messages)`
- **调用次数**：每次问答 1 次（仅 Reviewer 校验失败追加修复）
- **特点**：双盘 → **系统排盘事实翻倍**（主盘 + 对方盘各一套四柱/大运/流年/五行）；额外注入**合婚基础数据**（`match_basis`：双方盘 + 合婚分析）；注入相似命例、知识库检索、历史断事参考

## 说明

- **最少**：首轮合婚、无摘要/历史/命例/断事参考、知识库仅 1 条小结果 → 约 3647 字 / 6565 token（主要由 1407 系统 + 1700+200 双盘与合婚基础数据构成）。
- **典型**：中等历史 + 双盘事实 + 合婚基础数据 + 1 条相似命例 + 1~2 条知识库检索。
- **上限**：历史摘要 600 + 最近对话 1542 + 双盘事实 2200 + 合婚基础 1500 + 断事参考 1570 + 相似命例 795 + 知识库 2500，理论峰值，几乎不可能同时打满。
- **这是 Workflow 路径单次调用（B）token 最重的场景**——双盘事实 + 合婚基础数据 + 最大 worker 断法。
- 与 `workflow_regular.md` 关系：本场景 = 常规断事 + （双盘事实替换单盘）+ 合婚基础数据 + 最大 System。若加上调用 A（拆解，~1177~1397 字），合婚全开一轮约 **1400~13400 字 / 2500~24000 token**（仅主回答已含）。
