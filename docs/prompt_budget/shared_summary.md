# 公共调用 · 会话摘要（_maybe_summarize，后台线程）

- **调用位置**：`app/agent/xianzhi.py` 的 `Xianzhi._maybe_summarize()`
- **触发点**：在 `Xianzhi._persist_history()` 末尾调用；而 `_persist_history` 在 **Workflow 与 ReAct 两条路径跑完都会执行** → 这是一条**两条路径共用的独立后台 LLM 调用**，不归属某一专属路径。
- **触发阈值**：会话消息数距上次摘要又新增 **6 条**（= 3 轮对话）时触发（`new_since_last < 6` 直接 return）。首次在第 6 条消息（第 3 轮）结束时发生，之后每再累积 6 条做一次**增量**摘要（旧摘要 + 最近 6 条 → 新摘要）。
- **是否阻塞**：**已改为后台线程异步执行**（`threading.Thread(daemon=True)`），不阻塞当次用户请求收尾。旧注释「异步，不阻塞主流程」此前是假的（代码是同步 `invoke`），现已落实。
- **LLM 调用点**：`xianzhi.py:556` → `self.chat_model.invoke([SystemMessage, HumanMessage])`
- **产出**：≤600 字增量摘要，写入 `session_metadata`（旧摘要被合并保留）

## 说明

- **最少**：首次触发（第 3 轮结束）时旧摘要为空、最近 6 条较短 → 约 540 字 / 972 token。
- **典型**：已有旧摘要 + 最近 6 条中等长度 → 约 1492 字 / 2686 token。
- **上限**：旧摘要打满 600 + 最近 6 条均满 300 字 → 约 2634 字 / 4741 token。
- **成本归属**：本调用**独立于主回答**，是会话够长（>3 轮）后的额外开销，且每隔 3 轮才花一次。一轮问答的「主路径 token」需叠加它（若落在第 3/6/9… 轮）。
- **与 `react_loop` / `workflow_*` 文档的关系**：那几份表里的「合计字数」只算主路径的调用 A/B/C，**不含本摘要调用**。本调用另算。
- **实现细节**：阈值判断与数据快照（msg_count / 最近 6 条 / 旧摘要）在**主线程**完成以保证线程安全，仅 LLM 调用与落库在 daemon 线程内执行。
