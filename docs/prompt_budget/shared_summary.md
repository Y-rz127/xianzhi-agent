# 公共调用 · 会话摘要（maybe_summarize，后台线程）

> 注：摘要逻辑已于 8 月从 `xianzhi.py` 抽离至独立模块 `app/memory/summarizer.py`，本文按当前代码更新。

- **调用位置**：`app/memory/summarizer.py` 的 `maybe_summarize()`（summarizer.py:32）
- **触发点**：在 `Xianzhi._persist_history()` 末尾调用（xianzhi.py:598-601）；而 `_persist_history` 在 **Workflow 与 ReAct 两条路径跑完都会执行** → 这是一条**两条路径共用的独立后台 LLM 调用**，不归属某一专属路径。
- **触发阈值**：会话消息数距上次摘要又新增 **12 条**（= 6 轮对话）时触发（`_SUMMARY_TRIGGER_MESSAGES=12`，`new_since_last < 12` 直接 return）。首次在第 12 条消息（第 6 轮）结束时发生，之后每再累积 12 条做一次**增量**摘要（旧摘要 + 最近 12 条 → 新摘要）。旧版"每 6 条（3 轮）触发"已改为 12 条。
- **是否阻塞**：**后台 daemon 线程异步执行**（`threading.Thread(target=_run, daemon=True)`），不阻塞当次用户请求收尾；阈值判断与数据快照（msg_count / 最近 12 条 / 旧摘要）在**主线程**完成以保证线程安全。
- **LLM 调用点**：summarizer.py:62-67 → `chat_model.invoke([SystemMessage, HumanMessage])`
- **产出**：≤600 字增量摘要（`_SUMMARY_MAX_CHARS=600`，超长截断），`memory.save_summary` 写入会话元数据（旧摘要被合并保留）

## 输入 Token 预算（中文 1 字 ≈ 1.8 token）

| 段落 | 最少 | 典型 | 上限 | 说明 |
|---|---|---|---|---|
| System Prompt | 25 | 25 | 25 | 「你是会话摘要助手，只输出摘要文本，不输出任何解释。」（实测 25 字） |
| 摘要指令（固定） | 246 | 246 | 246 | `_SUMMARY_PROMPT` 固定模板（summarizer.py:19-29：摘要角色 + 保留事实清单 + 「【旧摘要】/【最近对话】/请输出新摘要」头，去插值实测 246 字） |
| 旧摘要 | 3 | 300 | 600 | 上次摘要（"（无）"占位 3 字起；增量合并，上限 600） |
| 最近对话 | 660 | 2400 | 3690 | 最近 **12** 条消息，每条 `ClassName: content[:300]`（12×≈307 上限；消息较短时 12×≈55 起） |
| **合计字数** | **~934** | **~2971** | **~4561** | |
| **合计 Token** | **~1681** | **~5348** | **~8210** | |

## 说明

- **最少**：首次触发（第 6 轮结束）时旧摘要为空、最近 12 条较短 → 约 934 字 / 1681 token。
- **典型**：已有旧摘要 + 最近 12 条中等长度 → 约 2971 字 / 5348 token。
- **上限**：旧摘要打满 600 + 最近 12 条均满 300 字 → 约 4561 字 / 8210 token。
- **成本归属**：本调用**独立于主回答**，是会话够长（>6 轮）后的额外开销，且每隔 6 轮才花一次。一轮问答的「主路径 token」需叠加它（若落在第 6/12/18… 轮）。
- **与 `react_loop` / `workflow_*` 文档的关系**：那几份表里的「合计字数」只算主路径的调用 A/B/C/D，**不含本摘要调用**。本调用另算。
- **摘要内容规范**：只保留命理事实（用户身份/已确认断事/对旧分析的修正反馈/待确认事项），闲聊问候天气流水账一律丢弃——这是摘要 prompt 固定模板里写死的规则。
