# Workflow 路径 · Reflextion 修复（_build_repair_messages，调用 C）

- **所属路径**：Workflow（`app/agent/xianzhi_workflow.py` 的 `XianzhiWorkflow`）
- **触发条件**：Worker 主回答（调用 B）产出后，经 `ReviewerWorker.review()`（纯正则/字符串校验，不调 LLM）发现命中事实红线 / 古籍杜撰 / 合规词等问题时，才调用本修复；**绝大多数轮次 review 通过，不触发**。
- **LLM 调用点**：`xianzhi_workflow.py` 的 `_build_repair_messages` → `self.chat_model.invoke(messages)`
- **调用次数**：每次问答 **0 或 1 次**（仅 B 被 Reviewer 打回时出现）
- **特点**：重放「用户问题 + 原回答 + Reviewer 问题列表 + 全部事实/知识上下文」，要求模型在不改事实的前提下改写。

| 合婚基础数据 | 0 | 0 | 1500 | 仅 match 域 |
| 命理规则检索 | 0 | 1500 | 2500 | 重放知识库（与 B 同口径） |

## 说明

- **最少**：chitchat 类被打回（worker=0、无事实/知识重放）+ 极短原回答 → 约 395 字 / 711 token。
- **典型**：常规断事被打回，重放单盘事实 + 知识库 + 中等原回答。
- **上限**：合婚双盘（事实 2200 + 合婚基础 1500）+ 知识库满 2500 + 长原回答 1500。
- **出现频率极低**：Reviewer 是规则校验，正常产出的命中率很低，多数会话全程不触发本调用。
- 与 `workflow_chitchat/theory/regular/match.md` 是**叠加**关系：一轮会话的总 token = 调用 B（+ 可能调用 A）+（若打回）调用 C。
